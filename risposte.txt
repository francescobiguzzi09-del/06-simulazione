1) il working tree è il punto dove ci si trova mentre si scrive il codice (ad esempio all'interno di VScode o thonny), la staging area è dove vengono salvati i i file o modifiche che devono essere committati, il repository locale contiene tutti i file del progetto che sono stati committati in locale.
dopo git add si passa dalla working tree alla staging area, con git commit si passa dalla staging alla repo locale.

2) git fetch permette di portare i file dalla repository remota a quella locale senza pero caricarli direttamente nella working tree, mentre git merge seguito dal nome del ramo permette di unire il ramo su cui ci troviamo con quello che abbiamo incluso nel comando, inoltre git merge è un comando che lavora esclusivamente in locale e quindi se si vuole mergiare un branch remoto, bisogna prima fare il fetch per portarlo nella repo locale.

3) Issue viene creata da un utente per segnalare un problema che deve essere fixxato e può assegnarlo a un collaboratore della repository; dopo aver creato l'issue, il collaboratore che è stato scelto per fixxare quella issue crea il branch per il fix, successivamente dopo averlo finito lo committa per metterlo mnella repo locale e poi lo pusha in remoto; una volta portato in remoto il fix il collaboratore crea una pull request al creatore dell'issue per permettere a esso di visualizzare il fix e quindi fare la review che se va a buon fine termina con il merge del branch fix sul branch che presentava l'issue.
